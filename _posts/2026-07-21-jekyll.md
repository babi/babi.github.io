如果你在寻找一种**简单、优雅、不需要后端**的方式搭建网站或博客，那么 Jekyll 很可能是你需要的工具。这个诞生于 2008 年的静态站点生成器，至今仍然是 GitHub Pages 的默认引擎，驱动着数以百万计的个人网站和项目文档。

本文将从零开始，带你全面了解 Jekyll 是什么、为什么用它、以及怎么用好它。

---

## 什么是 Jekyll？

[Jekyll](https://jekyllrb.com/)（发音：/ˈdʒiːkəl/）是一个用 Ruby 编写的**静态站点生成器**。它把 Markdown（写作内容）和 Liquid 模板（页面结构）结合起来，生成完整的 HTML 网站。

简单来说：你用 Markdown 写文章，Jekyll 会自动帮你生成 HTML 页面。

### 静态站点 vs 动态站点

| 特性 | 静态站点 (Jekyll) | 动态站点 (WordPress) |
|---|---|---|
| **页面生成** | 构建时预先生成所有 HTML | 每次访问实时查询数据库 |
| **服务器需求** | 任何静态文件服务器 | 需要 PHP + MySQL 运行时 |
| **加载速度** | 极快，无数据库查询 | 相对较慢 |
| **安全性** | 几乎没有攻击面 | 需要持续安全更新 |
| **评论系统** | 需要第三方服务（Disqus/giscus 等） | 自带数据库评论 |
| **动态功能** | 不适合 | 适合 |

### 为什么静态站点在回归？

有意思的是，Web 的最初形态就是静态站点。后来动态站点兴起，带来了评论、搜索、用户系统等丰富的交互能力。但随之而来的也是复杂性：服务器维护、数据库优化、安全更新、性能瓶颈……

静态站点生成器则回到了**"写好内容 → 生成页面 → 直接托管"**这个简单模型。对于博客、文档、作品集这类内容为主的网站，静态站点其实是比动态系统更优雅的解决方案。

## Jekyll 的核心概念

在开始使用 Jekyll 之前，需要理解几个关键概念。

### 1. 目录结构

一个典型的 Jekyll 项目长这样：

```
my-blog/
├── _config.yml          # 配置文件
├── _posts/              # 博客文章目录
│   └── 2026-07-21-hello.md
├── _layouts/            # 布局模板
│   ├── default.html
│   └── post.html
├── _includes/           # 可复用组件
│   ├── header.html
│   └── footer.html
├── _data/               # 数据文件
│   └── members.yml
├── assets/              # 静态资源
│   ├── css/
│   └── images/
├── _site/               # 构建输出（自动生成）
└── index.html           # 首页
```

### 2. Front Matter —— 前置元数据

每篇 Markdown 文件顶部的 `---` 之间的内容是**前置元数据 (Front Matter)**。它是文章/页面的"身份证"：

```markdown
---
layout: post          # 使用的布局模板
title: 我的文章        # 标题
date: 2026-07-21      # 日期
tags: [jekyll, web]   # 标签
author: babi          # 作者
---

这里是正文内容……
```

你在 Front Matter 中定义的变量，可以在模板中通过 `page.title`、`page.tags` 等方式引用。你甚至可以自定义任意变量。

### 3. Liquid 模板语言

Jekyll 使用 [Liquid](https://shopify.github.io/liquid/) 作为模板引擎。它用 `{% %}` 做逻辑控制，用 `{{ }}` 输出变量：

{% raw %}
```liquid
<h1>{{ page.title }}</h1>
<p>作者：{{ page.author }}</p>

{% for post in site.posts %}
  <article>
    <h2><a href="{{ post.url }}">{{ post.title }}</a></h2>
    <p>{{ post.date | date: "%Y-%m-%d" }}</p>
  </article>
{% endfor %}
```
{% endraw %}

Liquid 提供了一系列**过滤器 (filters)**，可以对变量做各种处理：

{% raw %}
```liquid
{{ "hello, world!" | capitalize }}    → "Hello, world!"
{{ post.date | date: "%Y-%m-%d" }}    → "2026-07-21"
{{ content | strip_html | truncate: 100 }}  → 截断纯文本到100字
```
{% endraw %}

### 4. 布局 (Layouts)

布局是页面的"外壳"。你可以定义多个布局（如 `post.html`、`page.html`、`default.html`），然后在 Front Matter 中指定使用哪个：

**`_layouts/post.html`：**

{% raw %}
```liquid
<!DOCTYPE html>
<html>
<head>
  <title>{{ page.title }}</title>
</head>
<body>
  {% include header.html %}
  
  <main>
    <article>
      <h1>{{ page.title }}</h1>
      {{ content }}
    </article>
  </main>
  
  {% include footer.html %}
</body>
</html>
```
{% endraw %}

关键点：布局中的 `{{ content }}` 就是当前页面的内容，布局嵌套布局是可以的——比如 `post.html` 可以继承 `default.html` 的公共结构。

### 5. Includes —— 组件复用

如果你有导航栏、页脚、侧边栏这些在多个页面重复出现的部分，把它们放在 `_includes/` 目录下，在布局或页面中引用即可：

{% raw %}
```liquid
{% include header.html %}
{% include footer.html %}
```
{% endraw %}

你也可以向 Include 传递参数：

{% raw %}
```liquid
{% include card.html title="你好" color="blue" %}
```
{% endraw %}

在 `_includes/card.html` 中用 `{{ include.title }}` 和 `{{ include.color }}` 接收。

### 6. 数据文件 (Data Files)

`_data/` 目录下的 YAML / JSON / CSV 文件会自动成为 `site.data` 对象。这是管理"非文章内容"的最佳方式：

**`_data/members.yml`：**

```yaml
- name: Alice
  role: Developer
- name: Bob
  role: Designer
```

在模板中：

{% raw %}
```liquid
{% for member in site.data.members %}
  <p>{{ member.name }} — {{ member.role }}</p>
{% endfor %}
```
{% endraw %}

适合管理团队成员列表、导航菜单项、配置项等结构化数据。

## 快速开始：在本地搭建 Jekyll

### 安装

Jekyll 是 Ruby gem，所以需要先安装 Ruby。macOS 和大多数 Linux 系统自带 Ruby，但版本可能较老。推荐用版本管理器安装较新的 Ruby：

**macOS：**

```bash
# 使用 Homebrew
brew install ruby

# 查看 Ruby 版本
ruby -v
```

**Ubuntu/Debian：**

```bash
sudo apt-get install ruby-full build-essential zlib1g-dev
```

**Windows：**

从 [rubyinstaller.org](https://rubyinstaller.org/) 下载安装包，安装时勾选 "Add Ruby executables to your PATH"。

### 安装 Jekyll

```bash
gem install jekyll bundler
```

### 创建新站点

```bash
# 方法一：用 new 命令创建
jekyll new my-blog
cd my-blog

# 方法二：直接初始化空目录（适合已有主题）
mkdir my-blog && cd my-blog
```

### 本地预览

```bash
bundle exec jekyll serve
```

打开浏览器访问 `http://localhost:4000`。加上 `--livereload` 参数，改文件后浏览器自动刷新：

```bash
bundle exec jekyll serve --livereload
```

Jekyll 默认会监控文件变化，修改后自动增量构建，体验非常流畅。

### 常用命令一览

| 命令 | 作用 |
|---|---|
| `jekyll build` | 构建站点，输出到 `_site/` |
| `jekyll serve` | 构建 + 启动本地服务器 |
| `bundle exec jekyll build` | 使用 Gemfile 指定的依赖来构建（推荐） |
| `jekyll clean` | 清理 `_site/` 和 `.jekyll-cache/` |
| `jekyll new 路径` | 快速创建新项目脚手架 |

## 写文章：核心工作流

### 命名规则

Jekyll 对文章文件的命名有严格要求：

```
YYYY-MM-DD-标题.md
```

例如 `2026-07-21-jekyll-guide.md`。这个命名决定了文章的 **永久链接 (permalink)** 默认路径。

### 文章 Front Matter 示例

```markdown
---
layout: post
title: Jekyll 完全入门指南
subtitle: 从概念到实践，一文掌握静态站点生成器
date: 2026-07-21 10:00:00 +0800
tags: [jekyll, tutorial]
author: babi
image: /assets/img/jekyll-banner.jpg
category: tutorial
---
```

### Permalink 定制

在 `_config.yml` 中可以配置文章的 URL 格式：

```yaml
# 常见的 permalink 格式
permalink: /:year/:month/:day/:title/     # /2026/07/21/jekyll-guide/
permalink: /:categories/:year/:title/     # /tutorial/2026/jekyll-guide/
permalink: /:title/                       # /jekyll-guide/
permalink: pretty                         # /jekyll-guide/ (同上一行)
```

### 草稿模式

不想发布但又想预览的文章可以放到 `_drafts/` 目录，文件不需要日期前缀：

```
_drafts/
└── unfinished-post.md
```

用 `--drafts` 参数预览：

```bash
bundle exec jekyll serve --drafts
```

这样只有你在本地能看到草稿，非常实用。

## 配置 (`_config.yml`)

`_config.yml` 是 Jekyll 站点的"大脑"。以下是一份常见配置：

```yaml
# 站点信息
title: 我的博客
description: 记录技术和生活
author: babi
lang: zh-CN

# 构建配置
markdown: kramdown
highlighter: rouge
permalink: /:year/:month/:title/
paginate: 10       # 每页显示文章数
paginate_path: "/page:num/"

# 插件
plugins:
  - jekyll-paginate
  - jekyll-sitemap
  - jekyll-feed
  - jekyll-seo-tag

# 排除文件（不会被构建）
exclude:
  - Gemfile
  - Gemfile.lock
  - node_modules
  - vendor

# 默认 Front Matter 值
defaults:
  - scope:
      path: ""
      type: "posts"
    values:
      layout: "post"
      author: "babi"
```

> ⚠️ **注意**：修改 `_config.yml` 后**必须重启** `jekyll serve` 才会生效。其他文件的修改则能实时增量更新。

## 插件生态

Jekyll 有丰富的插件系统。GitHub Pages 环境支持的插件有限，但在自建环境中几乎无所不能。

### 官方推荐插件

| 插件 | 作用 |
|---|---|
| `jekyll-paginate` | 分页功能 |
| `jekyll-sitemap` | 自动生成 sitemap.xml |
| `jekyll-feed` | 生成 RSS/Atom 订阅源 |
| `jekyll-seo-tag` | SEO 元标签 |
| `jekyll-redirect-from` | 页面重定向 |
| `jekyll-archives` | 按日期/标签/分类归档 |

### 安装插件三步走

1. 在 `Gemfile` 中添加 `gem "jekyll-xxx"`
2. 运行 `bundle install`
3. 在 `_config.yml` 的 `plugins` 列表中添加

```yaml
plugins:
  - jekyll-archives
```

### 高级插件示例

社区中还有一些非常有用的第三方插件：

- **`jekyll-paginate-v2`** —— 增强版分页，支持多分类分页
- **`jekyll-toc`** —— 自动生成文章目录
- **`jekyll-minifier`** —— 压缩 HTML/CSS/JS
- **`jekyll-git_metadata`** —— 注入 Git 元数据（最后修改时间等）

## 部署方式

Jekyll 最大的优势之一就是部署选项极其灵活。

### 1. GitHub Pages（免费，推荐）

把仓库推到 GitHub，自动构建部署。支持自定义域名和 HTTPS：

```bash
git push origin master
```

GitHub Pages 有[适配的插件白名单](https://pages.github.com/versions/)，如果只使用白名单内的插件和功能，完全不需要本地构建——推送 Markdown 源文件即可。

如果需要使用白名单外的插件（如 `jekyll-archives`），可以在本地构建后推送 `_site/` 目录，或者用 GitHub Actions 来自定义构建环境。

### 2. Netlify / Vercel（免费）

连接 GitHub 仓库，自动拉取、构建、部署。优势是构建环境更灵活：

```
# Netlify 构建命令
jekyll build

# 发布目录
_site
```

### 3. 自己托管

构建后把 `_site/` 目录放到任何静态文件服务器（Nginx、Apache、S3、CDN……）：

```bash
jekyll build
scp -r _site/* user@server:/var/www/html/
```

## Jekyll vs 其他静态站点生成器

| 特性 | Jekyll | Hugo | Next.js SSG | Hexo |
|---|---|---|---|---|
| **语言** | Ruby | Go | JavaScript | Node.js |
| **构建速度** | 中等（中大型站点慢） | **极快** | 中等 | 中等 |
| **学习曲线** | 低 | 中 | 中高 | 低 |
| **主题生态** | ⭐⭐⭐⭐⭐ 非常丰富 | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| **GitHub Pages 原生支持** | ✅ **是** | ❌ 需额外 CI | ❌ 需额外 CI | ✅ 有适配插件 |
| **适合场景** | 个人博客、文档、中小型站点 | 任何规模的站点 | 需要动态功能的大型站 | 个人博客 |

选择建议：

- **用 Jekyll** —— 追求简单、GitHub Pages 一键部署、博客为主
- **用 Hugo** —— 站点很大、要求极快构建速度、喜欢 Go 生态
- **用 Next.js** —— 需要 SSR、API 路由、React 组件等动态能力
- **用 Hexo** —— 习惯 Node.js 生态、纯博客需求

## 进阶技巧

### 1. 自定义集合 (Collections)

除了博客文章和页面，你还可以创建任意类型的**集合**：

```yaml
# _config.yml
collections:
  projects:
    output: true
    permalink: /projects/:path/
```

然后在根目录创建 `_projects/` 目录，放入 Markdown 文件。每个文件都有 Front Matter，你可以在模板中用 `site.projects` 访问它们。

适用于：作品集、菜谱、旅行记录、书评……任何你需要管理的结构化内容。

### 2. 用 Include 创建组件库

```liquid
{% raw %}
{% include card.html 
  title="Jekyll"
  description="静态站点生成器"
  image="/assets/img/jekyll.png"
%}
{% endraw %}
```

配合 CSS 可以快速搭建一个组件系统，就像用 React 组件一样。只是 Jekyll 在构建时就已经把它们组合好了。

### 3. 用 GitHub Actions 扩展构建

当 GitHub Pages 内置的白名单限制了你时，GitHub Actions 可以帮你自由构建：

```yaml
# .github/workflows/deploy.yml
name: Deploy Jekyll site
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.3'
      - run: bundle install
      - run: bundle exec jekyll build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./_site
```

这样你就可以使用任何 Jekyll 插件了。

## 常见问题

### Q：我不懂 Ruby 能用 Jekyll 吗？

完全没问题。你只需要知道几个命令——`jekyll new`、`jekyll serve`、`jekyll build`。大多数人用 Jekyll 写博客，根本不需要写 Ruby 代码。Liquid 模板语法非常简单，15 分钟就能上手。

### Q：Jekyll 还值得学吗？是不是过时了？

Jekyll 已经十多年了，但仍然是**最简单**的静态博客方案。它没有被"淘汰"，只是进入了成熟稳定期。对于写博客、做文档网站这个需求，它依然是综合成本最低的选择之一。GitHub Pages 官方推荐的引擎至今仍然是 Jekyll，这在可预见的未来不会改变。

### Q：Jekyll 适合做大型网站吗？

不太适合。当文章数量超过几千篇，构建时间会显著变长。此时 Hugo 或 Next.js 会更合适。Jekyll 的最舒适区域是：个人博客、项目文档、中小型内容站。

### Q：评论功能怎么实现？

推荐以下第三方评论系统：

- **[giscus](https://giscus.app/)** —— 基于 GitHub Discussions，无广告，推荐
- **[utterances](https://utteranc.es/)** —— 基于 GitHub Issues，轻量
- **[Disqus](https://disqus.com/)** —— 功能最全，但有广告
- 或者干脆不用评论系统，引导读者通过邮件/社交联系你

## 总结

Jekyll 是一个"返朴归真"的工具——在 Web 技术越来越复杂的今天，选择静态站点生成器本身就是一种有意识的选择：**专注于内容**，而不是系统。

它的优势可以归纳为三点：

1. **极低门槛** —— 会写 Markdown 就能写博客，GitHub Pages 一键部署
2. **极致性能** —— 预生成的 HTML，没有数据库查询，没有运行时开销
3. **零维护成本** —— 没有服务器需要更新，没有数据库需要备份

如果你正准备开始写博客或搭建个人网站——别犹豫了，从 Jekyll 开始吧。
